Primary Issue Pattern

Visual hierarchy is flat — everything competes for attention, nothing guides the eye to the primary action

Strongest Aspect

Core functionality works. Task creation flow is logical and the data model is sound.

P0 Blocker Prevents task completion, kills credibility, or blocks user groups
#1

Primary CTA is invisible

CRAP: Contrast
Gulf of Execution
Evidence

The 'Add Task' button uses the same gray background as inactive elements. At default viewport (1280px), it blends into the toolbar. No contrast differentiation from secondary actions.

Impact

All users. The single most important action on the page requires hunting. New users may not find it without exploring every element.

Fix
  1. Change 'Add Task' button to a solid accent color (e.g., #0a3cd9) with white text
  2. Increase button padding to 12px 24px for a larger click target
  3. Add a subtle shadow (0 1px 3px rgba(0,0,0,0.12)) to lift it from the surface
  4. Remove competing visual weight from secondary toolbar actions — make them text-only or icon-only
#2

Emoji used as status indicators

Affordance & Signifiers
Consistency break
Evidence

Task statuses use emoji: ⏳ (in progress), ✅ (done), ❌ (blocked). These render differently across browsers and OSes. On Windows Chrome, the 'blocked' emoji appears as a thin X that's nearly invisible at 14px.

Impact

All users on non-Apple platforms. Status is ambiguous or unreadable. Accessibility: screen readers may announce emoji names rather than semantic status.

Fix
  1. Replace all emoji status indicators with a single icon set (Lucide recommended — MIT license, consistent style)
  2. Use: Circle for todo, Loader for in-progress, CheckCircle for done, XCircle for blocked
  3. Add an aria-label to each status icon (e.g., aria-label='In Progress')
  4. Ensure icons have a minimum size of 16px with appropriate color coding
#3

No visual hierarchy in task list

Typography
Cognitive overload
Evidence

All task rows use identical 14px regular weight text. Task name, assignee, due date, and status all compete at the same visual level. No typographic differentiation between primary content (task name) and metadata.

Impact

All users. Scanning a list of 20+ tasks requires reading every cell. Users cannot quickly identify which tasks need attention.

Fix
  1. Task name: 14px, font-weight 600 (semibold), color #1a1511
  2. Metadata (assignee, date): 12px, font-weight 400 (regular), color #6b5c4c
  3. Overdue dates: 12px, font-weight 500, color #b91c1c
  4. Add 4px vertical gap between task name and metadata row within each task card
P1 Important Significant friction, degrades experience but doesn’t block
#4

Spacing inconsistency across cards

CRAP: Repetition
Consistency break
Evidence

Task cards use 16px internal padding in the list view but 12px in the board view. Gap between cards is 8px in list view and 12px in board view. The inconsistency creates subtle visual noise.

Impact

Experienced users who switch between views. The interface feels unpolished, reducing trust in the product.

Fix
  1. Standardize internal card padding to 16px in all views
  2. Standardize gap between cards to 12px in all views
  3. Use a 4px-based spacing scale: 4, 8, 12, 16, 24, 32, 48
#5

No empty state for new projects

Feedback & System Status
Feedback gap
Evidence

Creating a new project leads to a blank white page with only the project title and an empty task table header. No guidance on what to do next.

Impact

New users. The blank page feels broken. Users don't know if they need to add tasks, invite members, or configure settings first.

Fix
  1. Add an empty state illustration or icon (simple, minimal — a checklist outline)
  2. Add a clear headline: 'No tasks yet'
  3. Add a single CTA: 'Create your first task' styled as the primary action
  4. Optionally add 1-2 lines of context: 'Tasks help you track work. Create one to get started.'
#6

Delete task has no confirmation

Error Prevention & Recovery
Gulf of Execution
Evidence

Clicking the trash icon on a task row immediately deletes it with no confirmation dialog and no undo option. The action is instant and irreversible.

Impact

All users. Accidental deletion of tasks with notes, comments, and attachments is permanent. High-stakes slip with no recovery path.

Fix
  1. Add a confirmation dialog: 'Delete [task name]? This cannot be undone.'
  2. Frame the dialog around what will be lost: 'This task and its 3 comments will be permanently deleted'
  3. Preferred: implement undo (5-second toast with 'Undo' action) instead of confirmation — faster and safer
P2 Polish Minor visual issues, copy improvements, micro-interactions
#7

Sidebar navigation lacks active state

Consistency & Predictability
Gulf of Evaluation
Evidence

The left sidebar lists projects but the currently selected project has no visual differentiation from the others. Only the main content area changes.

Impact

Users with multiple projects. Disorientation when switching between projects — 'which project am I looking at?'

Fix
  1. Add a left border accent (3px, solid, accent color) on the active project row
  2. Set active row background to rgba(10, 60, 217, 0.06)
  3. Use font-weight 600 for active project name vs 400 for inactive
#8

Decorative gradient on header serves no purpose

CRAP: Contrast
Cognitive overload
Evidence

The page header uses a blue-to-purple gradient background that draws attention away from the task list content. The gradient carries no semantic meaning.

Impact

Low severity individually, but contributes to overall visual noise. The gradient competes with functional elements for attention.

Fix
  1. Replace gradient with a flat, light neutral background (#f0f3fc or #ffffff)
  2. If branding is needed, use a thin 3px accent bar at the top of the page instead
